# MeshLink v4.8 — connection/discovery recovery patch

## Changes
- BLE scanner now retries after Android scan failure, unavailable scanner, or thrown start errors, using bounded exponential delay (1.5–15 seconds).
- BLE advertiser now retries after advertising failure or thrown start errors, using bounded exponential delay (2–15 seconds).
- Stop cancels scheduled retries so Mesh Mode off does not restart BLE in the background.
- UI peer list is deduplicated by stable authenticated node ID, not BLE address, because BLE addresses can change.
- The active peer list now requires a live tracked client or server-side link and an authenticated crypto session; it no longer declares a still-connected peer stale solely because its advertisement timestamp is old.
- Stale unconnected discovery records are pruned from memory.

## Known limitations / validation
- This archive is source-patched, not a verified APK. A full Gradle build and multi-phone physical BLE test have not been completed in this environment.
- Android may impose connection limits; the mesh is not a full all-to-all physical connection graph. Multi-hop delivery relies on relay routing.
- The app should be tested with Android Bluetooth logs to confirm whether the remaining failure is scanning, GATT connection, service discovery, notification setup, or HELLO authentication.
